## 생성기를 만든 과정

포털 중심과 방향으로 후보 방의 Pose를 구한 뒤, 셀과 추가 예약 영역을 월드 공간으로 변환하여 충돌을 검사합니다. 통과한 후보는 PlacedBlock으로 기록하고 다음 시나리오 단계로 확장합니다.

선형 배치만으로는 여러 출입구의 분기를 처리하기 어려웠습니다. 한 가지를 먼저 확장하고 형제로 돌아오는 DFS와 후보 재시도를 도입했습니다. 같은 깊이의 유일 단계가 이미 사용되면 다른 가지는 Intermediate 말단으로 대체했습니다. 실패 시 목록 길이로 저장한 체크포인트 이후의 블록을 역순 제거하고 연결 및 유일 단계 소유권을 복구했습니다.

당시 구현은 모든 형제 후보 조합을 탐색하는 완전 탐색이 아니었습니다. 생성 성공을 항상 보장하거나 Warframe 알고리즘을 그대로 재현했다고 주장하지 않습니다. WFC 내부 생성은 초기 검토 주제였으며 이 저장소의 구현 성과로 포함하지 않습니다.

## 현재 코드에서 읽을 위치

- [BlockPlacementCalculator](../Source/Runtime/BlockPlacementCalculator.cs): 포털 정렬과 배치 Pose
- [BlockReservationBuilder](../Source/Runtime/BlockReservationBuilder.cs): 월드 예약 박스와 AABB 계산
- [ReservationOverlap](../Source/Runtime/ReservationOverlap.cs): 정밀 겹침 검사
- [PlacedBlock](../Source/Runtime/PlacedBlock.cs): 배치 결과·예약 박스·경계 보관
- [TemplateBaseBuilder](../Source/Runtime/TemplateBaseBuilder.cs): 시나리오 탐색, 후보 배치, 체크포인트 복구와 마감

“기존 생성 알고리즘 유지”는 **후반 통합 편집기와 규칙 시스템을 연결할 때의 제약**입니다. 프로젝트 초기부터 생성기를 개발하지 않았다는 뜻이 아닙니다.
